# Public naming check for "AnyMCP"

**This is not legal clearance.** Registry availability says nothing about trademark rights. This is a read-only
search so nobody assumes the name or package identifiers are free. Nothing was registered, purchased or contacted.

The product was called **MyCP** during development. The owner renamed it **AnyMCP** on 2026-11-13. The earlier
check for "MyCP" found an npm conflict and a possible Class 42 trademark; it is superseded by this page.

## npm registry (checked 2026-11-13 with `npm view`)

| Name | Result |
|---|---|
| `anymcp` | **Taken, by a closely related product.** Version 0.3.2, MIT, first published 2026-06-10, described as a "self-contained MCP server that turns any website into a runnable MCP server, in-process", from the public repository `github.com/Francklin9999/mcpify`. Same problem space, same name. |
| `anymcp-bridge`, `anymcp-cli`, `any-mcp` | Not found (404) |
| `@anymcp/bridge` | Not found (404). A 404 does not prove that the `@anymcp` scope is free to register. |
| `@dilipna/anymcp-bridge`, `@dilipna/anymcp` | Not found (404). A scope tied to the owner's npm account cannot be taken by anyone else. |

## What this means

* **Recommended package name for the bridge: `@dilipna/anymcp-bridge`** (command: `anymcp-bridge`). It cannot be
  confused at install time with the existing `anymcp` package, and only the owner can publish under the scope.
* **The product name itself has a live conflict.** An unrelated project already ships an npm package called `anymcp`
  that does something very similar. Users searching for "anymcp" will find it, and its maintainer may hold rights
  in the name. Before any store listing or package is published, the owner should decide whether to keep the name.
  If kept, a proper trademark search is still needed: this page checked registries only, not trademark databases.
* Nothing has been published. All workspace packages are `private` (`anymcp-protocol`, `anymcp-bridge`,
  `anymcp-extension`, `anymcp-fixture`, `anymcp-eval`). The publishable bridge package is generated by
  `npm run package` and is not published.
* The Chrome Web Store assigns the extension id and shows the listing name; check the store for lookalikes again
  at submission time.

## Identifiers that changed with the rename (migration)

| What | Before (pre-release) | Now | Compatibility |
|---|---|---|---|
| Bridge state folder | `~/.mycp` | `~/.anymcp` | If only `~/.mycp/state.json` exists it is copied once, so an existing pairing keeps working. Delete `~/.mycp` afterwards. |
| State folder override | `MYCP_HOME` | `ANYMCP_HOME` | `MYCP_HOME` is still read. |
| "Private area" attribute for site authors | `data-mycp-ignore` | `data-anymcp-ignore` | Both are honoured. |
| MCP tool names | `mycp_status`, `mycp_get_run` | `anymcp_status`, `anymcp_get_run` | Not kept: re-list tools in the client. |
| MCP server key in client config | `mycp` | `anymcp` | Re-add the server in the client (`claude mcp remove mycp`, then the new command). |
| Bridge command and file | `mycp-bridge`, `mycp-bridge.mjs` | `anymcp-bridge`, `anymcp-bridge.mjs` | Update client configs that point at the old file. |
| Extension storage | — | unchanged | No `chrome.storage` key contained the old name, so tools, grants and pairing survive. |
